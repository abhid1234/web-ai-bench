Pitch 1 — LiteRT Certified Partner Network

TL;DR — "Intel Inside for edge AI"

  • The gap: LiteRT has exactly two informal partnerships (Hugging Face, Qualcomm) — no certification standard, no public application surface, no co-marketing calendar, no tier structure. ExecuTorch (Meta) is building native toolchain lock-in across Meta's app ecosystem. LiteRT needs ecosystem lock-in at the hardware, training, and deployment layer before the window closes (18–24 months).
  • The pitch: A formal "Works on LiteRT" certification program across 4 partner classes — Hardware, Training Platforms, Deployment Tools, Model Hubs. Public partner portal at ai.google.dev/edge/partners. Annual LiteRT Partner Summit. "Powered by LiteRT" badge with trademark license. In 3 years: every NPU chip ships LiteRT pre-validated, every training platform has a LiteRT export button, every DevOps tool has a LiteRT pipeline stage.
  • Partnerships background required: Managing Harness, Datadog, and Lovable at Google Cloud provides direct CI/CD and DevOps ecosystem relationships — not a cold pitch.
  • First 3 partners: Qualcomm (Hardware — Strategic tier, existing relationship to formalize), Hugging Face (Model Hub — Strategic tier, existing relationship to deepen), Roboflow (Training Platform — Community tier, the exemplar that proves the onboarding path works).
  • Duration: 6-month initiative. Partnerships PM leads program design + partner outreach. LiteRT DevRel owns toolkit and portal. Legal owns trademark.

§1. The Problem

LiteRT has ad-hoc partnerships today — Qualcomm's Hexagon NPU delegate exists, Hugging Face hosts litert-community, Roboflow exports .tflite. But none of these are formal. There is no shared standard, no public application surface, and no co-marketing engine. The result:

  • When a new hardware vendor wants to certify their NPU for LiteRT, there is no documented process. They email someone on the team and hope for a response.
  • When a training platform wants to add a "Deploy to LiteRT" button, there is no spec for what that means or what badge they earn.
  • When Lead PM wants to say "LiteRT has X partners," there's no list.
  • When a developer Googles "does LiteRT work with [tool]?", there's no answer.
The ExecuTorch threat is not about runtime quality — it's about ecosystem lock-in. ExecuTorch v1.2.0 (April 1, 2026) powers Instagram, WhatsApp, Ray-Ban Smart Glasses, and Meta Quest 3. Every Meta developer defaults to ExecuTorch. Every PyTorch developer is drawn toward ExecuTorch. LiteRT's answer cannot be "our runtime is faster" — it must be "our ecosystem is bigger and better connected." That ecosystem does not exist yet. This pitch builds it.

§2. The Four Partner Classes

Partners belong to one class based on where they sit in the on-device AI workflow. The certification standard differs by class. Tiers (Community / Integration / Strategic) exist within each class.

ClassWhat they certifyBadge earnedYear-1 target count
Hardware
(NPU / GPU / DSP vendors)		Their NPU or GPU delegate runs the LiteRT certification test suite at a specific runtime version without accuracy regression (<1%) or latency degradation (>10%) on the reference benchmark model set."Certified LiteRT Hardware Partner v2.1.4"2–3 (Qualcomm as Strategic anchor)
Training Platforms
(ML training tools, AutoML, labeling)		One-click or single-command export to .tflite from their training UI or CLI. Export produces a model that loads in @litertjs/core and the LiteRT Android SDK without modification."Exports to LiteRT"2–3 (Roboflow as Community exemplar)

(Model repositories and discovery)		Verified .tflite or @litertjs/core-compatible model cards with standardized benchmark data (latency per backend, accuracy delta from FP32, conversion provenance). Produced using litert push --auto-card."LiteRT-Ready Models"1–2 (HF as Strategic anchor)
Pitch 2 linkage: The LiteRT DevKit CLI and GitHub Actions (Pitch 2) are the technical standard that Deployment Tool partners certify against. Harness becomes the first Deployment Tool class partner because it implements a native LiteRT pipeline stage using the DevKit. Pitch 1 and Pitch 2 are designed to ship in parallel — the partner program needs the certification standard, and the DevKit is that standard.

§4. The First Three Partners — Detailed Design

Partner 1: Qualcomm — Hardware Class, Strategic Tier

What already exists: Qualcomm's Hexagon NPU delegate for LiteRT exists and works. It's used in Snapdragon-powered Android devices. But the relationship is informal — there's no certification standard, no co-marketing commitment, no public listing.

What this pitch formalizes:

  • Certification: Qualcomm runs the LiteRT hardware certification test suite (Partnerships PM designs the spec; Matt reviews) on Hexagon NPU at each major LiteRT release. Results are published to the partner portal. Badge: "Certified LiteRT Hardware Partner v2.1.4 — Qualcomm Hexagon NPU."
  • Co-marketing: Joint press release at program launch. Qualcomm listed as Strategic Hardware partner on the portal. One co-authored technical blog post per year ("Running LiteRT on Snapdragon — benchmark deep dive").
  • Roadmap access: Qualcomm gets pre-release access to LiteRT versions for early delegate validation. They provide early feedback on NPU API changes.
  • Summit: Qualcomm presents at the annual LiteRT Partner Summit (their NPU roadmap relevant to LiteRT developers).

Hardware certification test suite design (what Partnerships PM builds):

LiteRT Hardware Certification Test Suite v1.0

Purpose: Validate that a hardware delegate (NPU/GPU/DSP) runs the reference
         model set within acceptable accuracy and latency bounds.

Reference model set (15 models covering all major task types):
  - sentence-transformers/all-MiniLM-L6-v2 (sentence embedding)
  - google/mobilenet_v3_small (image classification)
  - google/efficientdet-lite0 (object detection)
  - google/movenet-singlepose-lightning (pose estimation)
  - distilbert-sst2 (text classification)
  - whisper-tiny.en (speech-to-text, encoder only)
  - ... [full list in certification-test-suite-v1.md]

Pass criteria (per model):
  Accuracy: delta from FP32 reference ≤ 1.0%
  Latency (median, 100 runs): ≤ 110% of Pixel 8 GPU-delegate baseline
  Reliability: 0 crashes across 1,000 inference runs

Partner 2: Hugging Face — Model Hub Class, Strategic Tier

What already exists: litert-community org with 93 models (as of Apr 30, 2026). 16 in the Web Models collection — all LiteRT-LM / Gemma text generation. Zero @litertjs/core models. Three Gemma Demo Spaces. Zero co-authored blog posts about @litertjs/core.

What this pitch formalizes:

  • HF Hub library filter: Submit PR adding litert as a recognized library in the HF Hub filter (alongside transformers, onnx, gguf). Compounds forever once merged — every litert model becomes filterable.
  • Model Hub certification standard: HF litert-community models that meet the standard get a "LiteRT-Ready" badge on their model card. Standard: model card includes standardized benchmark table (produced by litert bench), conversion provenance, usage code snippet for @litertjs/core and LiteRT Android SDK.
  • Co-marketing: One co-authored blog post per year (the Pitch 2 DevKit launch blog post is the first — "We shipped 12 web models in 8 weeks using LiteRT DevKit"). Cross-published on huggingface.co/blog and ai.google.dev/edge/blog. HF listed as Strategic Model Hub partner on the portal.
  • HF Spaces: Three @litertjs/core Spaces in litert-community (produced as the Pitch 2 launch moment — sentence similarity, real-time image classification, sentiment analysis). Each Space links to the model card, which links to the partner portal.

Partner 3: Roboflow — Training Platform Class, Community → Integration Tier

The exemplar story: Roboflow is the Community-tier pilot — the first partner to go through the formal onboarding path. The goal is to demonstrate that the path works, then use Roboflow's graduation (Community → Integration) as a case study in the program launch materials.

Phase 1 — Community tier (months 2–4):

  • Roboflow ships one model card on litert-community (EfficientDet-Lite0, via the Pitch C reference app — already designed)
  • Roboflow publishes one blog post ("Train in Roboflow, run in the browser with LiteRT.js")
  • Roboflow earns Community tier badge. Listed on the partner portal under Training Platforms.

Phase 2 — Integration tier graduation (months 5–6):

  • Roboflow adds a "Deploy to LiteRT" export option in their training UI (single click → .tflite download)
  • This is the Training Platform class certification: "Export from Roboflow → loads in @litertjs/core without modification"
  • Partnerships PM co-designs the export spec with Roboflow's eng team. Matt validates the output.
  • Roboflow earns Integration tier + "Exports to LiteRT" badge. Featured at the Partner Summit.
Why Roboflow is the right Community → Integration exemplar: Roboflow's 200k+ CV developer audience is exactly the LiteRT target user. When Roboflow features the "Deploy to LiteRT" button, those 200k developers see it organically — no additional marketing from Google needed. Roboflow gets a differentiated feature. LiteRT gets 200k warm developer introductions.

The trademark license that permits this requires Google Legal + Google Trademark / Brand Protection sign-off. Timeline: 4–6 weeks minimum from when the request is submitted. Start in week 3 of this initiative, not week 7. If the license slips past week 9, launch the portal without the badge and add it in v1.1 once legal lands.
